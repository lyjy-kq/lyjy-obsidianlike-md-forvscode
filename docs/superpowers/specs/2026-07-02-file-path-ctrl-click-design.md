# 文件路径 Ctrl+点击跳转设计

## 背景

FlowMD 当前已经支持对 Markdown 链接和外链执行点击打开，但普通文本中的源码路径，例如 `src\webview\codemirror\extensions\livePreview\decorations.ts:22`，在 Live Preview 中还不能直接 `Ctrl/Cmd+点击` 跳转到 VS Code 对应文件与位置。

在结果落盘的文档里，也常会出现相对当前 md 文件的跳转片段，例如 `../lib_run_single.py:25`。这类路径必须以当前 md 文件所在目录为基准进行解析，否则用户在查看生成结果时无法直接跳转到对应源码位置。

## 目标

在 Live Preview 中支持识别普通文本里的文件路径表达式，并在 `Ctrl/Cmd+点击` 时打开 VS Code 中对应文件，并跳转到指定行号或范围。

## 范围

- 支持相对路径、工作区根目录路径、Windows 绝对路径以及 `/`、`\` 两种分隔符。
- 支持相对于当前 md 文件的路径解析，特别是 `../lib_run_single.py:25` 这类结果落盘场景中的回跳。
- 绝对路径必须保持兼容，命中后直接打开对应文件，不参与相对路径回退。
- 支持以下位置后缀：
  - `:行`
  - `:行:列`
  - `:起始行-结束行`
  - `:起始行:起始列-结束行:结束列`
- 支持路径出现在普通句子中，只要前后存在自然边界，例如空格、标点、行首或行尾。
- 当前文档位于 `src\docs\sss.md` 时，`src\webview\...` 这类从工作区根目录开始的路径也要可跳转。

## 非目标

- 不新增新的 Markdown 语法。
- 不改变现有锚点链接的点击行为。
- 不强制给普通路径增加额外视觉装饰，本期以正确识别与跳转为先。

## 方案

### Webview 侧

- 新增纯函数，用于在一行文本中识别“光标所在位置是否命中文件路径表达式”。
- 在 Live Preview 的 `mousedown` 事件处理中，优先保留现有 `.cm-md-link` 行为。
- 如果没有命中现有链接，且用户按下了 `Ctrl/Cmd`，则按点击坐标定位到文档位置，并从所在行提取路径表达式。
- 命中后发送既有 `openFile` 消息，把完整路径文本连同行列后缀一起交给扩展侧解析。

### 扩展侧

- 新增纯函数解析 `openFile` 的原始文本，拆分出“文件路径部分”和“行列/范围部分”。
- 路径解析顺序：
  - 如果原始路径是绝对路径，则直接规范化并打开，不做相对回退。
  - 如果是相对路径，先按当前 Markdown 文件所在目录解析。
  - 如果文件不存在，再按当前文件所在 workspace folder 根目录解析。
  - 如果仍不存在，再保留第一个候选结果，维持可预测的兜底行为。
- 打开文件时改为调用 `vscode.open` 并传入 `selection`，从而直接跳转到指定行号或选中范围。

## 边界处理

- 句子中的路径前后允许出现中文或英文标点，但不会把标点本身计入路径。
- `C:\` 这样的 Windows 盘符前缀不能被误判为 `:行号`。
- 已有 Markdown 链接中的目标地址如果本身包含 `:22`、`:21-33` 后缀，也应复用同一套扩展侧解析逻辑。
- `../lib_run_single.py:25` 这种相对当前 md 文件的路径必须能够解析到真实文件，并保留第 25 行的跳转位置。

## 测试策略

- 为路径识别纯函数编写单元测试，覆盖句中路径、反斜杠路径、行列范围和边界截断。
- 为扩展侧解析与解析顺序编写单元测试，覆盖当前目录命中、workspace 根目录回退、相对当前 md 文件的父级路径、绝对路径直开、行列范围转换。
- 手动验证 Live Preview 中 `Ctrl/Cmd+点击` 的真实交互链路。
