# 2. 需求总结

本次修复要同时处理 Mermaid 预览链路中的多个交互问题：

- Mermaid 放大预览不应再因为缓存引用缺失而报 `mermaidSvgCache 未定义`。
- 图片与 Mermaid 的复制失败应更稳定，避免误判成失败。
- 复制按钮上方的状态提示在空消息时不应露出蓝色矩形底。
- 浮层标题栏应展示可读的名称；当没有名称时显示灰白斜体占位。
- 设置打包后，应关闭 debug/控制台输出或让其按配置收敛，不把调试信息带到正式包的默认体验里。

# 3. 需求背景

当前预览功能已经能完成图片和 Mermaid 的放大、复制，但在实际使用中出现了多个互相关联的问题：

- Mermaid 放大预览打开后会直接报渲染失败。
- 复制图片时会被判定失败，影响用户复制图片到聊天工具或文档工具。
- 复制状态提示在没有文字时仍占着一块蓝底矩形，影响视觉。
- 放大浮层标题现在过于静态，缺少对当前内容名称的表达，也不利于后续修改时同步回源码。
- 打包后的正式体验不应默认把调试日志和控制台输出暴露得过重。

本次修改边界：

- 只处理预览浮层、复制状态、标题栏、Mermaid 渲染缓存和设置输出相关行为。
- 不扩展新的文件格式或外部存储方案。
- 不重做整个 live preview 架构。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 放大预览应正常复用正文渲染缓存。
- Mermaid 复制按钮应继续优先复制图片，失败时回退到文本。
- 图片复制按钮应稳定写入剪贴板，不误报失败。
- 复制状态框只在有文本时显示，空状态必须隐藏。
- 浮层标题应可表达图片或 Mermaid 的名称来源；若无名称，显示灰白斜体占位文案。
- 调试输出应在正式打包场景下按配置关闭或收敛。

## 4.2 非功能需求

- 可维护性：标题来源、复制状态和调试开关分别收敛，不互相耦合。
- 可读性：新增函数、字段、常量必须有中文注释。
- 异常处理要求：缓存缺失、图片复制失败、标题缺省和设置关闭都要有明确回退。
- 日志要求：开发时可追踪，正式包默认不噪音化。
- 注释要求：遵守“注释优先”规则。

## 4.3 不做的内容

- 不新增独立的 Mermaid 导出设置页。
- 不新增服务端或扩展主进程的复杂桥接协议。
- 不改动右键菜单、大纲面板和普通正文编辑行为。

# 5. 方案制定

采用“修复缓存导入 + 统一标题来源 + 空状态隐藏 + 设置输出收敛”的组合方案。

- 在 Mermaid 浮层渲染模块中恢复对正文缓存状态的正确导入，确保渲染路径可访问 `mermaidSvgCache`。
- 图片和 Mermaid 复制逻辑统一校验成功路径，失败时只在真正失败时提示。
- 状态提示节点在无文本时直接隐藏，避免蓝色矩形残留。
- 为图片和 Mermaid 浮层标题增加可编辑来源：
  - 图片标题优先使用 alt 或图像名。
  - Mermaid 标题优先使用可识别的图表名；没有名字时显示灰白斜体占位。
- 设置打包后，按配置控制 debug 与控制台输出，避免正式包默认输出过多调试信息。

异常处理策略：

- Mermaid 缓存缺失或导入失败时，浮层直接进入错误态，不影响编辑器其它内容。
- 复制链路失败时继续显示简洁失败反馈。
- 标题缺省时显示占位，不留空白块。

是否影响已有功能：

- 影响图片/ Mermaid 预览浮层的标题与复制交互。
- 影响设置加载后的日志输出可见性。
- 不影响正文渲染与文档内容编辑的核心流程。
