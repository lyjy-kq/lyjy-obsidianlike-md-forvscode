# 2. 需求总结

修复 Mermaid 预览点击复制后仍然失败的问题。
用户点击 Mermaid 预览或浮层中的复制按钮时，应复制当前已经渲染出来的图表图片，而不是复制 Mermaid 源码文本，也不应因为 SVG 图片格式写入不被当前 webview 环境支持而直接失败。

# 3. 需求背景

当前 Mermaid 复制逻辑已经改为从当前 DOM 中读取渲染后的 SVG 节点，但后续直接以 `image/svg+xml` 写入浏览器剪贴板。
在 VS Code webview 与 Chromium 剪贴板能力组合下，`navigator.clipboard.write()` 对图片格式、用户激活状态和 `ClipboardItem` 类型支持较敏感，直接写入 SVG 仍可能失败。

因此需要改为更通用的 PNG 图片写入方式，同时继续复用当前已经渲染出来的 SVG，避免点击时重新渲染 Mermaid。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制按钮继续从当前已经渲染的 SVG 节点取图。
- 复制时将 SVG 转换为 PNG 图片二进制。
- 剪贴板写入使用 `image/png` 类型。
- 正文内 Mermaid 复制和浮层内 Mermaid 复制都应走同一套修复后的逻辑。
- 复制失败时继续显示现有简洁失败提示。

## 4.2 非功能需求

- 可维护性：Mermaid 复制转换逻辑保留在 `previewOverlay.ts` 中，避免 `widgets.ts` 增加图片编码细节。
- 可读性：新增或修改的函数、常量需要保留中文注释。
- 性能要求：仅在用户点击复制时转换 PNG，不影响普通 Mermaid 渲染。
- 兼容性要求：不改变图片预览复制逻辑，不改变 Mermaid 正文渲染与浮层渲染逻辑。
- 异常处理要求：SVG 不存在、PNG 转换失败或剪贴板写入失败时返回失败状态，由现有按钮状态提示展示。
- 日志要求：不新增调试日志。
- 注释要求：新增代码必须说明功能、参数和返回值。

## 4.3 不做的内容

- 不复制 Mermaid 源文本。
- 不新增下载图片功能。
- 不修改 VS Code webview 权限配置。
- 不改变浮层缩放、拖动和关闭交互。

# 5. 方案制定

采用“当前 SVG 节点转 PNG 后写入剪贴板”的方案。

- `copyMermaidRenderedImageSafely()` 继续接收包含 SVG 的 DOM 容器。
- 函数内部序列化当前 SVG 节点。
- 使用现有 `convertSvgToPngBlob()` 将 SVG 绘制到 canvas 并输出 PNG Blob。
- 使用 `ClipboardItem({ 'image/png': ... })` 写入剪贴板。
- 为降低用户激活丢失风险，优先把 PNG Blob 的 Promise 直接交给 `ClipboardItem`，让 `navigator.clipboard.write()` 尽早发生在点击处理链路中。
- 如果当前环境不支持 Promise 形式的 `ClipboardItem` 数据，则退回为先等待 PNG Blob，再写入剪贴板。

异常处理策略：

- 任一步失败都返回 `false`。
- 上层按钮继续通过 `createPreviewActionGroup()` 展示 `复制失败`。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览的复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染缓存与高度测量逻辑。
