# 2. 需求总结

清理 Mermaid 旧图片消息桥接链路，删除扩展侧和共享类型中已废弃的 `copyMermaidImageToClipboard`、`mermaidImageCopyResult` 以及对应的消息类型和处理分支，避免代码继续依赖这条旧桥接。

# 3. 需求背景

旧 Mermaid 图片复制链路已经被新的实现替代，但代码中仍保留消息常量、共享消息类型和消息处理分支。
继续保留这些旧定义会让代码阅读和维护产生歧义，也会增加未来误用这条废弃链路的风险。

本次修改仅做清理收口，不重新设计 Mermaid 复制方案，也不影响其他图片保存或正文编辑消息链路。

# 4. 需求分析

## 4.1 功能需求

- 删除 `copyMermaidImageToClipboard` 相关消息常量或分支。
- 删除 `mermaidImageCopyResult` 相关消息常量或分支。
- 从共享类型中移除对应消息接口或联合类型引用。
- 从扩展侧消息处理逻辑中移除旧 Mermaid 图片复制处理分支。
- 从 Webview 主入口消息转发逻辑中移除对应结果分支。

## 4.2 非功能需求

- 可维护性：只保留当前实际使用的消息契约，避免废弃定义残留。
- 可读性：清理后代码路径应更直接，不保留无效注释和死分支。
- 兼容性要求：不得影响图片保存、正文编辑、主题切换等现有消息链路。
- 异常处理要求：清理废弃分支时不改变其他消息的错误处理逻辑。
- 注释要求：如需新增说明，必须使用中文注释。

## 4.3 不做的内容

- 不新增新的 Mermaid 复制实现。
- 不调整 Mermaid 渲染或预览 UI。
- 不修改未在范围内的其他文件。
- 不回退已有的其他改动。

# 5. 方案制定

采用“删除旧定义 + 删除对应处理分支”的方式完成收口。

- `src/shared/messageTypes.ts`：移除旧 Mermaid 图片消息常量。
- `src/shared/types.ts`：移除旧 Mermaid 图片消息接口和联合类型引用。
- `src/extension/editorProvider.ts`：删除旧消息分支以及不再需要的处理引用。
- `src/webview/main.ts`：删除旧结果消息转发分支。

异常处理策略：

- 删除后如果出现编译报错，以编译器报错为准继续收口，确保没有残留引用。
- 若某文件存在编码异常，则仅做最小必要编辑并记录阻塞点。

是否影响已有功能：

- 只影响已废弃的 Mermaid 旧图片消息链路。
- 不影响当前有效的图片保存、编辑器同步和其他 Webview 消息。
