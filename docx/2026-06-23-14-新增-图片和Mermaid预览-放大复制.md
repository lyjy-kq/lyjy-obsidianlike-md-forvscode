# 2. 需求总结

为图片预览和 Mermaid 图预览补充一个轻量的查看器入口。
用户在正文内看到图片或 Mermaid 预览时，可以点击右下角的放大按钮打开独立浮层，在浮层内对内容进行正常缩放、拖动查看，并可通过复制按钮快速复制对应源内容。

# 3. 需求背景

当前图片和 Mermaid 都只提供正文内预览，遇到较大图片或复杂图表时不便细看。
需要补一个不打断编辑流程的查看方式，让用户在不离开当前页面的前提下，快速进入大图/大图表查看模式，同时保留复制入口方便复用链接或源文本。

# 4. 需求分析

## 4.1 功能需求

- 图片预览右下角新增极小放大按钮。
- Mermaid 预览右下角新增极小放大按钮。
- 两类预览均新增紧邻放大按钮的复制按钮。
- 点击放大按钮后，打开独立浮层。
- 浮层中图片和 Mermaid 都可以缩放、拖动查看。
- 点击复制按钮时，复制当前预览自身的渲染图片内容。
- 图片场景复制图片自身。
- Mermaid 场景复制 Mermaid 渲染后的图表图片，不复制 Mermaid 源文本。

## 4.2 非功能需求

- 可维护性：预览浮层逻辑尽量抽离为独立模块，避免 `widgets.ts` 继续膨胀。
- 可读性：新增代码必须保持中文注释完整，关键函数、字段、模块顶部都要有说明。
- 性能要求：浮层仅在点击时创建，不影响正文内常规渲染性能。
- 兼容性要求：不破坏现有图片 Ctrl/Cmd 点击打开本地文件行为，不破坏 Mermaid 正文渲染。
- 异常处理要求：当复制失败、图片加载失败、Mermaid 渲染失败时，要给出可见的降级表现。
- 日志要求：避免新增噪音日志，仅在必要的调试路径保留。
- 注释要求：新增文件、函数、字段均需要规范中文注释。

## 4.3 不做的内容

- 不修改正文内容本身的 Markdown 结构。
- 不新增额外配置项。
- 不实现浏览器级别的文件下载、导出或批量复制。
- 不改动右侧大纲、编辑器模式切换等无关功能。

# 5. 方案制定

采用“正文内轻量入口 + 独立浮层查看器”的方案。

- 正文内的图片和 Mermaid 预览保持原有渲染方式。
- 在预览容器右下角叠加两个小按钮：放大与复制。
- 放大按钮点击后创建固定定位浮层，浮层内承载原始图片或 Mermaid SVG。
- 浮层通过鼠标滚轮控制缩放，通过拖拽控制平移。
- 复制按钮直接复用浏览器剪贴板图片写入能力，复制图片二进制或 Mermaid 渲染后图片。
- 图片与 Mermaid 共用一套浮层交互壳，减少重复实现。

异常策略：

- 图片或 Mermaid 资源不可用时，仍保留按钮和错误提示。
- 复制失败时显示短暂失败反馈，不中断编辑。

是否影响已有功能：

- 仅新增按钮和浮层，不修改现有正文渲染逻辑的核心行为。
- 现有 Ctrl/Cmd 点击本地图片打开文件的逻辑保持不变。
