# 2026-06-19 31 修复 图片渲染 统一支持 wiki 与空格路径
## 背景

当前 FlowMD 的预览区已经能渲染一部分标准 Markdown 图片，例如 `![](assets/paste-xxxx.png)`。
但是以下写法仍然会出现无法渲染或解析不一致的问题：

- `![](./assets/image 1.png)`
- `![](assets/image 1.png)`
- `![[./assets/image 1.png]]`
- `![[assets/image 1.png]]`

这类差异会让同一张本地图片在不同写法下表现不一致，影响正文编辑体验。

## 目标

1. 统一支持 Markdown 图片和 Obsidian wiki 图片两种写法。
2. 统一支持相对路径前缀 `./assets` 与 `assets`。
3. 统一支持文件名中带空格的图片路径。
4. 保持现有图片渲染样式与预览行为一致，不影响其他 Markdown 语法。

## 范围

### 需要修改

- `src/webview/codemirror/extensions/livePreview/plugin.ts`
- `src/webview/codemirror/extensions/livePreview/widgets.ts`
- `src/webview/codemirror/extensions/livePreview/helpers.ts`

### 不需要修改

- 图片下载到 `assets` 的右键菜单逻辑
- 其他正文语法渲染逻辑
- 大纲、代码块、表格等非图片模块

## 实现方案

1. 在预览渲染层增加统一的图片解析逻辑。
2. 将 Markdown 图片与 wiki 图片统一转换为同一种图片 widget 渲染。
3. 对图片路径做最小化规范化处理：
   - 保留相对路径语义
   - 支持 `./`、`assets/`、`./assets/`
   - 支持空格文件名
4. 保持当前焦点编辑区逻辑不变，只在非焦点区域进行图片替换渲染。

## 验收标准

1. 以上四种图片写法都能在预览区正常显示。
2. 同一张本地图片在 Markdown 写法与 wiki 写法下渲染一致。
3. 不影响普通文本、链接、标题、代码块等其他内容的显示。
4. 构建可以正常通过。
