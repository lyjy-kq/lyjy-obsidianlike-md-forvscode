# 2. 需求总结

当图片或 Mermaid 预览复制失败时，页面右下角不再展示过长的错误气泡文案，而是以更轻量、更统一的失败状态提示用户。
本次修复只调整失败提示的文案与表现方式，不改变现有图片复制、Mermaid 复制和预览浮层的核心逻辑。

# 3. 需求背景

当前图片和 Mermaid 预览共用同一套复制失败提示。
该提示使用了较长的错误文案，且语义偏向“图片写入环境限制”，在界面上显得过于强烈，也不够适合 Mermaid 场景。

需要把失败提示收敛为更短、更通用的状态提示，让用户能看到失败结果，但不会被过长的红色气泡干扰预览区域。

# 4. 需求分析

## 4.1 功能需求

- 图片预览复制失败时，按钮旁状态提示显示简洁文案。
- Mermaid 预览复制失败时，按钮旁状态提示显示同一套简洁文案。
- 失败状态仍然可见，用户能明确知道复制没有成功。
- 复制按钮本身的短暂反馈逻辑保持不变。

## 4.2 非功能需求

- 可维护性：失败提示文案集中管理，避免图片和 Mermaid 复制提示分裂。
- 可读性：相关常量和辅助逻辑必须有中文注释。
- 兼容性：不改动现有 clipboard 写入流程，不影响原有复制成功路径。
- 异常处理要求：复制失败后仍然要有可见反馈，但不扩大错误信息。
- 注释要求：新增的常量、函数、字段都要补充中文说明。

## 4.3 不做的内容

- 不修改图片预览和 Mermaid 预览的复制实现链路。
- 不新增额外配置项。
- 不处理浏览器或 webview 权限本身的问题。
- 不改动浮层的放大、拖动和关闭逻辑。

# 5. 方案制定

采用“统一失败状态文案 + 保留现有复制逻辑”的方案。

- 在预览浮层模块中提取统一的复制失败状态常量。
- 图片和 Mermaid 复制失败时都使用同一条更简短的状态文案。
- 保留按钮短暂闪烁反馈，帮助用户快速确认操作结果。
- 只调整失败提示呈现，不改变成功提示和复制数据来源。

异常处理策略：

- 复制仍然失败时继续显示状态提示，不抛出新的交互错误。
- 如果状态节点不存在，保持静默降级，不影响主流程。

是否影响已有功能：

- 不影响图片 Ctrl/Cmd 点击打开本地文件。
- 不影响 Mermaid 渲染与浮层预览。
- 不影响现有剪贴板权限判断和失败回退。
