# 2. 需求总结

将 Mermaid 预览的复制能力统一收口为“复制当前渲染 SVG 的纯文本”。
复制时直接读取当前 DOM 中已渲染的 SVG，并将其字符串内容写入剪贴板，不再保留 HTML 剪贴板、`ClipboardItem`、图片剪贴板或相关转码实现。

# 3. 需求背景

当前 Mermaid 预览复制链路经历了 HTML 与图片两类方案，代码路径较分散，维护成本较高。
在 webview 场景下，当前渲染出的 SVG 已足够满足复制需求，继续保留 HTML 或图片剪贴板实现会增加兼容性风险与理解成本。

本次修改的目标是收口复制逻辑，确保：

- 复制入口统一
- 复制内容明确
- 不再依赖图片剪贴板能力
- 不再保留 HTML / ClipboardItem 相关分支

# 4. 需求分析

## 4.1 功能需求

- Mermaid 预览复制按钮继续从当前已渲染 DOM 中查找 `svg`。
- 复制时将 `svg` 序列化为纯文本字符串写入剪贴板。
- 若未找到 `svg`，复制失败并返回 `false`。
- 若浏览器原生剪贴板可用，则直接写入纯文本。
- 若原生剪贴板不可用，则回退到现有 webview 消息链路写入纯文本。
- Mermaid 正文预览与浮层预览继续共用同一复制入口。

## 4.2 非功能需求

- 可维护性：删除无关的 HTML、ClipboardItem、图片剪贴板辅助实现，降低代码复杂度。
- 可读性：保留并补充中文注释，说明文件用途、函数职责与字段含义。
- 性能要求：仅在用户点击复制时读取当前 SVG 并进行序列化。
- 兼容性要求：不再依赖图片剪贴板能力；复制结果以纯文本为准。
- 异常处理要求：SVG 缺失、剪贴板写入失败时返回失败状态。
- 日志要求：保留必要调试日志，便于定位复制失败原因。
- 注释要求：满足中文注释优先规范。

## 4.3 不做的内容

- 不新增 HTML 剪贴板复制。
- 不新增 `ClipboardItem` 相关实现。
- 不走图片剪贴板链路。
- 不修改图片预览复制逻辑。
- 不修改 Mermaid 渲染逻辑本身。

# 5. 方案制定

采用“当前 SVG -> 纯文本 -> 剪贴板”的方案。

- 从渲染完成的容器中查找 `svg`。
- 使用 `XMLSerializer` 将 `svg` 转成纯文本字符串。
- 优先使用现有 webview 消息链路写入纯文本。
- 如果消息链路不可用，则回退到浏览器原生 `navigator.clipboard.writeText()`。
- 不保留 HTML 或图片剪贴板分支。

异常处理策略：

- 未找到 SVG 时直接返回失败。
- 任意序列化或写入异常都返回失败。
- 上层按钮保持现有失败提示，不额外扩展交互。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览的复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染与浮层缩放、拖动交互。
