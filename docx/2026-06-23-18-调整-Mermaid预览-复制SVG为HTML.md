# 2. 需求总结

将 Mermaid 预览复制按钮改为直接复制当前渲染出来的 SVG 文本。
这样用户在粘贴到支持 SVG 的编辑器、文档或代码工具时，可以继续保留矢量结构，同时不再依赖图片剪贴板权限或系统原生命令。

# 3. 需求背景

当前 Mermaid 复制经过多轮图片剪贴板方案后仍不稳定。
webview 图片剪贴板写入、扩展主进程原生图片剪贴板写入都存在环境兼容问题，并且在部分环境中会直接失败。

Mermaid 已经在 webview 内完整渲染为 SVG，可以直接复用该 SVG 作为复制内容，减少转码和系统剪贴板限制带来的失败概率。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制按钮继续读取当前已渲染出来的 SVG 节点。
- 复制时直接写入当前 SVG 字符串。
- 复制时优先调用 Webview 可用的纯文本剪贴板链路。
- 如当前环境不支持 Webview 剪贴板，则回退到浏览器原生 `writeText()`。
- Mermaid 正文预览和浮层预览都使用同一套复制逻辑。
- 复制失败时继续展示简洁状态提示。

## 4.2 非功能需求

- 可维护性：复制逻辑集中在 `previewOverlay.ts`。
- 可读性：新增函数、常量、注释均需中文说明。
- 性能要求：仅在点击复制时读取 SVG 和写入剪贴板。
- 兼容性要求：不再依赖图片剪贴板；只复制 SVG 文本，不额外依赖富文本剪贴板能力。
- 异常处理要求：SVG 不存在或浏览器剪贴板不支持时，返回失败状态。
- 日志要求：保留必要的调试日志，便于观察是否成功发起复制。
- 注释要求：符合“注释优先”的源文件规范。

## 4.3 不做的内容

- 不再走 PNG 转换流程。
- 不再调用扩展主进程写图片剪贴板。
- 不再写入 `text/html` 剪贴板内容。
- 不新增系统临时文件处理。
- 不修改图片预览复制逻辑。

# 5. 方案制定

采用“SVG -> 纯文本剪贴板”的方案。

- 从当前 Mermaid 预览节点取出 `svg`。
- 优先复用 Webview 到扩展的文本剪贴板链路。
- 如果链路不可用，则回退到浏览器原生 `writeText()`。
- 复制时保持原始 SVG 文本内容不变。

异常处理策略：

- SVG 缺失、浏览器不支持、写入失败时都返回失败。
- 上层仍然使用现有按钮状态提示 `复制失败`。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染和浮层交互。
