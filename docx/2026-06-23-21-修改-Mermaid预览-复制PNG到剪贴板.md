# 2. 需求总结

将 Mermaid 预览复制按钮改为把当前渲染出来的 Mermaid 图转换为 PNG 后写入剪贴板。
复制结果应优先被识别为图片，方便在聊天软件、文档工具和支持图片粘贴的应用中直接使用。

# 3. 需求背景

当前 Mermaid 复制已经支持 SVG 文件本体，但用户实际希望粘贴得到的是 PNG 图片。
SVG 文本或 SVG 文件本体在很多目标应用里仍会作为源码处理，而不是直接显示成图片。

Mermaid 已经在 webview 内完整渲染为 SVG，可以在前端将 SVG 绘制到 canvas 再导出为 PNG Blob，随后直接写入剪贴板。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制按钮继续读取当前已渲染出来的 SVG 节点。
- 复制时将 SVG 转成 PNG Blob。
- 优先将 PNG Blob 作为图片写入剪贴板。
- 同时保留 `text/plain` 作为回退内容，便于图片剪贴板不可用时仍可复制 SVG 文本。
- Mermaid 正文预览和浮层预览都使用同一套复制逻辑。
- 复制失败时继续展示简洁状态提示。

## 4.2 非功能需求

- 可维护性：复制逻辑集中在 `previewOverlay.ts`。
- 可读性：新增函数、常量、注释均需中文说明。
- 性能要求：仅在点击复制时做一次 SVG 到 PNG 的转换。
- 兼容性要求：优先使用浏览器/网关可支持的图片剪贴板能力，不额外依赖 HTML 包装。
- 异常处理要求：SVG 不存在、canvas 转换失败或剪贴板不支持时，返回失败状态。
- 日志要求：保留必要的调试日志，便于观察是否成功发起复制。
- 注释要求：符合“注释优先”的源文件规范。

## 4.3 不做的内容

- 不再走 PNG 文件落盘到扩展主进程的旧桥接方案。
- 不再使用 `text/html` 作为 Mermaid 复制主格式。
- 不新增系统临时文件处理。
- 不修改图片预览复制逻辑。

# 5. 方案制定

采用“SVG -> canvas -> PNG Blob -> 剪贴板”的方案。

- 从当前 Mermaid 预览节点取出 `svg`。
- 用 `DOMParser` 读取 SVG 的 `width`、`height` 或 `viewBox`，得到画布尺寸。
- 把 SVG 转成 `Blob` 或 `data URL` 后绘制到 `canvas`。
- 从 canvas 导出 PNG `Blob`。
- 优先使用 `navigator.clipboard.write()` 写入 `ClipboardItem`，内容类型为 `image/png`，同时附带 `text/plain` 回退。
- 如果浏览器环境不支持图片剪贴板，则回退到 `writeText()`，复制纯文本 SVG。

异常处理策略：

- SVG 缺失、canvas 转换失败、浏览器不支持、写入失败时都返回失败。
- 上层仍然使用现有按钮状态提示 `复制失败`。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染和浮层交互。
