# 2. 需求总结

修复 Mermaid 预览复制按钮在复制 PNG 图片时出现 `Document is not focused`，导致只能回退复制 SVG 文本的问题。
复制动作应继续优先写入 PNG 图片，并在不可用时保持纯文本 SVG 回退。

# 3. 需求背景

当前 Mermaid PNG 复制流程会先把 SVG 异步转换成 PNG Blob，再调用 `navigator.clipboard.write()`。
在 VS Code Webview 环境中，异步转换期间文档可能失去焦点或用户激活状态过期，从而触发剪贴板写入失败。

日志中同一次操作出现两次 `Mermaid copy found SVG` 和两次失败信息，说明按钮事件也可能在 `mousedown` 与 `click` 两个阶段重复触发。

本次修改边界：

- 只修复 Mermaid 预览复制 PNG 的焦点与重复触发问题。
- 不恢复旧的扩展侧 PNG 文件落盘桥接。
- 不修改图片预览复制逻辑。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制按钮继续读取当前 DOM 中已渲染的 SVG。
- 复制时继续将 SVG 转成 PNG Blob。
- 调用 `navigator.clipboard.write()` 时应尽量保持在用户交互触发链路内。
- PNG 写入失败时继续回退复制 SVG 文本。
- 同一次鼠标操作只能触发一次复制。
- Mermaid 正文预览和浮层预览继续共用同一套复制逻辑。

## 4.2 非功能需求

- 可维护性：修复集中在 `previewOverlay.ts`，避免引入新的跨模块链路。
- 可读性：新增类型、函数和关键逻辑使用中文注释说明。
- 性能要求：仅在点击复制时执行 SVG 到 PNG 转换。
- 兼容性要求：优先使用浏览器原生 Clipboard API；不支持 Promise 数据的环境继续回退文本。
- 异常处理要求：剪贴板写入失败、PNG 转换失败或 SVG 缺失时返回失败或回退文本。
- 日志要求：保留能区分 PNG 成功、PNG 失败和文本回退的调试日志。
- 注释要求：遵守源文件顶部说明、函数说明、字段说明和关键代码说明规则。

## 4.3 不做的内容

# 5. 方案制定

采用“提前发起剪贴板写入请求 + Promise 延迟提供 PNG 数据”的方案。

- 在读取 SVG 后立即构造 `ClipboardItem`。
- `image/png` 字段传入由 SVG 转 PNG 得到的 Promise，而不是等待 Promise 完成后再调用剪贴板写入。
- `text/plain` 字段继续放入 SVG 文本 Blob，作为同一 ClipboardItem 的文本内容。
- 立即调用 `navigator.clipboard.write()`，降低 VS Code Webview 在异步转码后失焦的概率。
- 如果浏览器不支持该能力或写入失败，则调用现有文本复制回退。
- 将按钮事件入口改为 `pointerdown` 主导，并在后续 `click` 中稳定吞掉同一次操作，避免重复复制。

异常处理策略：

- SVG 节点不存在：直接返回失败。
- Clipboard API 不可用：回退文本复制。
- PNG Promise 或 write 失败：记录调试日志并回退文本复制。
- 文本回退失败：返回失败，由上层展示 `复制失败`。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染和浮层交互。
