# 2. 需求总结

修复 FlowMD 渲染界面里的搜索输入框失焦问题。
用户点击搜索框后，光标应稳定停留在搜索输入框中，能够连续输入和编辑搜索内容，不应跳回正文编辑区域。

# 3. 需求背景

当前渲染界面在 `viewer` 模式下仍会保留编辑器宿主的点击聚焦逻辑。
当用户点击搜索面板输入框时，编辑器宿主会把焦点重新抢回正文，从而表现为输入光标闪一下就消失，键盘输入落到正文区域。

这个问题会直接破坏搜索功能的可用性，尤其是在需要频繁修改搜索关键字时影响明显。

本次修改边界：

- 只修复搜索输入框被正文编辑器抢焦点的问题。
- 不修改搜索面板的渲染结构。
- 不修改正文编辑、滚动、选区和大纲逻辑。

# 4. 需求分析

## 4.1 功能需求

- 用户在渲染界面点击搜索输入框时，输入焦点应停留在搜索输入框上。
- 用户在搜索框中输入字符时，键盘输入应持续作用于搜索框。
- 用户点击正文内容时，编辑器仍应按原逻辑获得焦点。
- 用户点击搜索面板中的其他交互控件时，不应被正文编辑器强行接管焦点。

## 4.2 非功能需求

- 可维护性：修复逻辑集中在编辑器鼠标聚焦处理上，避免跨模块扩散。

- 性能要求：仅在鼠标按下事件触发时增加一次轻量判断，不引入额外轮询。
- 兼容性要求：继续兼容 `viewer`、`live` 和 `source` 模式下的现有行为。
- 异常处理要求：对非元素型事件目标保持原有兜底逻辑，不引入空指针错误。
- 日志要求：本次修复不新增日志噪音。
- 注释要求：遵守源文件顶部说明、函数说明和关键逻辑说明规范。

## 4.3 不做的内容

- 不调整主题、样式和按钮布局。

# 5. 方案制定

采用“保留正文聚焦、排除搜索面板等交互控件”的方案。

- 编辑器原先在 `viewer` 模式下会对整块编辑器 DOM 的 `mousedown` 进行聚焦处理。
- 该逻辑将搜索面板输入框也视为正文区域，导致点击搜索框时焦点被正文重新抢走。
- 修复时在 `mousedown` 处理中增加目标元素判断：
  - 如果点击目标位于搜索面板或其他表单交互控件中，则不执行正文聚焦。
  - 如果点击目标属于正文内容区域，则继续执行原有聚焦逻辑。
- 这样可以让搜索输入框正常输入，同时不影响正文点击进入编辑状态。

异常处理策略：

- 如果事件目标不是 DOM 元素，则保持原有正文聚焦兜底逻辑。
- 如果搜索面板未来改名或结构变化，则需要重新核对排除条件。

是否需要新增配置：

- 不需要新增配置。

是否影响已有功能：

- 仅影响 `viewer` 模式下点击搜索输入框和其他交互控件时的聚焦行为。
- 正文点击聚焦、选区和滚动行为保持不变。
