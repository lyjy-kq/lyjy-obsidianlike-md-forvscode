# 2026-06-19 28 调整 粘贴图片 自动保存assets并插入链接

## 背景

当前 FlowMD 已经支持图片拖拽、文件选择和剪贴板图片保存，但粘贴图片的行为还不够贴近 Obsidian / Markdown 的习惯：

1. 粘贴事件会优先让 `text/plain` 走普通文本处理，导致部分“图文混合剪贴板”里的图片无法被识别。
2. 图片默认保存目录仍偏向旧的 `images` 目录命名。
3. 插入到正文里的图片链接语法还没有统一整理，用户希望兼容 Markdown 和 Obsidian 风格的写法。

## 目标

1. 当剪贴板里实际包含图片时，优先按图片处理。
2. 图片自动保存到 Markdown 文档同级的 `assets` 目录下。
3. 插入到正文时自动生成图片链接，兼容以下格式：
   - `![](./assets/image 1.png)`
   - `![](assets/image 1.png)`
   - `![[./assets/image-1 1.png]]`
   - `![[assets/image-1 1.png]]`
4. 拖拽、文件选择和粘贴三种入口保持一致。

## 范围

### 需要修改

- `src/webview/imageDropHandler.ts`
- `src/extension/imageSaveHandler.ts`
- `src/extension/configManager.ts`
- `package.json`

### 不需要修改

- Markdown 正文其它渲染逻辑
- 大纲逻辑
- 主题和代码块渲染逻辑

## 实现方案

1. 调整 Webview 粘贴逻辑，优先检测 `image/*` 剪贴板项。
2. 保存成功后，根据当前文档内容中已有的图片语法风格，自动选择 Markdown 图片语法或 Obsidian wiki 图片语法。
3. 统一保存目录默认值为 `assets`，并保持路径校验与去重逻辑不变。
4. 对外表现上，用户看到的插入结果将是可直接访问的相对图片链接。

## 验收标准

1. 从系统剪贴板粘贴图片时，能够自动保存成文件并插入正文。
2. 保存出来的图片文件位于文档同级 `assets` 目录下。
3. 插入文本能正确显示为 Markdown 图片或 Obsidian wiki 图片链接。
4. 文档里即使同时存在 `![](...)` 和 `![[...]]`，粘贴图片也不会插入失败。
