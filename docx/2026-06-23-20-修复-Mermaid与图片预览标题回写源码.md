# 2. 需求总结

本次修复要让图片和 Mermaid 的放大预览标题不仅能显示名称，还能在用户编辑后同步回写到原始 Markdown 源码中。
当内容没有可用名称时，标题栏保持空白，不再额外展示占位文案。

# 3. 需求背景

当前预览浮层已经可以展示图片和 Mermaid，并能显示一个标题节点，但标题还只是静态文本，不能反映用户实时修改，也不能回写到源文件。
这会导致预览中的名称与正文内容脱节，尤其在用户通过预览侧快速修正图片 alt 文本或 Mermaid 标题时，无法形成编辑闭环。

本次修改边界：

- 只处理预览标题的可编辑与回写能力。
- 不改变正文渲染、复制、缩放、拖动等既有行为。
- 不引入新的外部存储或独立元数据文件。

# 4. 需求分析

## 4.1 功能需求

- 图片预览浮层标题应默认展示图片名称或 alt 文本。
- Mermaid 预览浮层标题应默认展示可读名称；若无名称则保持空白。
- 用户在标题栏修改文字后，应立即或在失焦时同步回写到对应 Markdown 源码。
- 标题为空时应保持空白，不再自动回退为占位文本。
- 回写失败时应有明确提示或静默回退，不影响预览本身。

## 4.2 非功能需求

- 可维护性：标题编辑、源码定位、文本替换逻辑要拆分清楚。
- 可读性：新增文件、函数、字段和关键流程都要补中文注释。
- 兼容性要求：不破坏现有图片和 Mermaid 的预览与复制链路。
- 异常处理要求：找不到源码锚点、文本未变化、编辑冲突时要安全退出。
- 日志要求：仅保留必要调试信息，避免打包后噪音输出。
- 注释要求：符合“注释优先”规范。

## 4.3 不做的内容

- 不扩展新的预览面板布局。
- 不新增独立的标题管理页面。
- 不重构整个 live preview widget 体系。

# 5. 方案制定

采用“预览标题可编辑 + 源码定位回写”的方案。

- 在图片和 Mermaid 预览浮层中，将标题节点改为可编辑元素。
- 通过 widget 构造参数把源码位置或可编辑锚点一并传入浮层。
- 图片标题回写到 Markdown 图片 alt 文本，保持原有语法结构。
- Mermaid 标题回写到可用的源码注释或信息位，避免破坏图表渲染语义。
- 如果当前内容没有名称，则保持空白，并允许用户输入后生成新的名称。

异常处理策略：

- 源码锚点缺失：不执行写回，仅保留预览内编辑结果或回退占位。
- 编辑结果与原文本相同：不触发文档修改。
- 多次快速输入：使用去抖或失焦提交，避免频繁写入。

是否影响已有功能：

- 会影响图片与 Mermaid 的预览标题渲染与交互。
- 不影响复制、缩放、拖动以及正文同步逻辑。
