# 2. 需求总结

将 Mermaid 预览复制按钮改为复制当前渲染出来的 SVG 文件本体。
复制结果应尽量保留 SVG 的原始矢量结构，方便在支持 SVG 粘贴的应用中直接作为图像内容使用。

# 3. 需求背景

当前 Mermaid 复制已经从图片剪贴板切换为 SVG 文本复制，稳定性有所提升，但复制结果仍然以纯文本形式存在。
用户希望复制的是 SVG 文件自身，而不是 HTML 包装后的内容，也不是普通文本源码。

Mermaid 已经在 webview 内完整渲染为 SVG，因此可以直接将该 SVG 以 `image/svg+xml` 形式写入剪贴板，减少中间格式转换。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制按钮继续读取当前已渲染出来的 SVG 节点。
- 复制时优先将 SVG 作为 `image/svg+xml` 写入剪贴板。
- 同时提供纯文本 SVG 作为回退内容，便于不支持 SVG 图像剪贴板的环境继续使用。
- Mermaid 正文预览和浮层预览都使用同一套复制逻辑。
- 复制失败时继续展示简洁状态提示。

## 4.2 非功能需求

- 可维护性：复制逻辑集中在 `previewOverlay.ts`。
- 可读性：新增函数、常量、注释均需中文说明。
- 性能要求：仅在点击复制时读取 SVG 和写入剪贴板。
- 兼容性要求：尽量优先使用 `image/svg+xml`，不再依赖 HTML 包装。
- 异常处理要求：SVG 不存在或浏览器剪贴板不支持时，返回失败状态。
- 日志要求：保留必要的调试日志，便于观察是否成功发起复制。
- 注释要求：符合“注释优先”的源文件规范。

## 4.3 不做的内容

- 不再走 PNG 转换流程。
- 不再调用扩展主进程写图片剪贴板。
- 不再使用 `text/html` 作为 Mermaid 复制主格式。
- 不新增系统临时文件处理。
- 不修改图片预览复制逻辑。

# 5. 方案制定

采用“SVG 节点 -> `image/svg+xml` 剪贴板”的方案。

- 从当前 Mermaid 预览节点取出 `svg`。
- 将 SVG 字符串包装为 `Blob`，类型设置为 `image/svg+xml`。
- 优先使用 `navigator.clipboard.write()` 写入 `ClipboardItem`，同时附带 `text/plain` 回退。
- 如果浏览器环境不支持 `ClipboardItem` 或 `write()`，则回退到 `writeText()`，复制纯文本 SVG。
- 若浏览器剪贴板能力完全不可用，则返回失败。

异常处理策略：

- SVG 缺失、浏览器不支持、写入失败时都返回失败。
- 上层仍然使用现有按钮状态提示 `复制失败`。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染和浮层交互。
