# 2. 需求总结

修复 Mermaid 图片复制在 VS Code webview 中持续失败的问题。
用户点击 Mermaid 预览复制按钮后，应由 webview 生成 PNG 图片数据并发送给扩展侧，再由扩展侧调用系统原生命令写入系统图片剪贴板。

# 3. 需求背景

当前方案已经尝试过在 webview 中直接使用 `navigator.clipboard.write()` 写入 SVG 或 PNG 图片，但该能力在 VS Code webview 中受用户激活、权限和 Chromium 剪贴板支持限制，仍然失败。

需要绕开 webview 图片剪贴板权限限制，把图片写入动作迁移到扩展主进程中处理。

# 4. 需求分析

## 4.1 功能需求

- Mermaid 复制仍然从当前已经渲染的 SVG 节点取图。
- Webview 将 SVG 转为 PNG data URL。
- Webview 通过 `postMessage` 将 PNG data URL 发送给扩展侧。
- 扩展侧将 PNG 写入临时文件。
- Windows 下扩展侧调用 PowerShell 原生命令把 PNG 写入系统图片剪贴板。
- 扩展侧向 Webview 回传复制成功或失败结果。
- Webview 根据回传结果展示复制成功或失败状态。

## 4.2 非功能需求

- 可维护性：消息类型和数据结构集中到 shared 类型文件中。
- 可读性：新增函数、接口、字段必须有中文注释。
- 性能要求：仅在用户点击复制时生成 PNG，不影响常规 Mermaid 渲染。
- 兼容性要求：优先完整支持 Windows；其他平台返回明确失败，避免静默无效。
- 异常处理要求：PNG 解码、临时文件写入、原生命令失败都要回传失败结果。
- 日志要求：扩展侧记录失败原因，便于后续排查。
- 注释要求：新增代码遵守中文注释要求。

## 4.3 不做的内容

- 不复制 Mermaid 源文本。
- 不新增保存到 assets 的功能。
- 不实现 macOS 和 Linux 的原生图片剪贴板写入。
- 不改变图片预览复制链路。

# 5. 方案制定

采用“Webview 生成 PNG + Extension 原生写入剪贴板”的方案。

- Webview 侧：
  - 继续复用当前 Mermaid SVG 节点。
  - 使用 canvas 将 SVG 转为 PNG Blob。
  - 将 PNG Blob 转为 data URL。
  - 生成 requestId 并发送 `copyMermaidImageToClipboard` 消息。
  - 等待扩展侧 `mermaidImageCopyResult` 回传结果。

- Extension 侧：
  - 接收 PNG data URL。
  - 校验并解码 PNG 数据。
  - 写入系统临时目录。
  - Windows 下调用 PowerShell STA 脚本写入系统剪贴板图片。
  - 回传复制结果。
  - 尝试清理临时文件。

是否影响已有功能：

- 影响 Mermaid 正文预览与浮层预览的复制按钮。
- 不影响图片预览复制按钮。
- 不影响 Mermaid 渲染、缓存和浮层查看。
